# ConsequenceStudio — Ecosystem Integration

ConsequenceStudio is the DAW-grade creator interface. It orchestrates ConsequenceTheory, ConsequencePoet, ConsequenceStream, and ConsequenceLedger **without importing Poet or Theory packages**. All cross-service communication uses typed clients in `packages/stream`.

## Ecosystem map

| Repo | Role | Studio relationship |
|------|------|---------------------|
| **ConsequenceStudio** (this repo) | DAW UI, supervision, session orchestration | Primary application |
| **ConsequenceTheory** | CMTE analysis, harmonic/rhythmic structure | Studio reads frames via Stream / theory engine bridge |
| **ConsequencePoet** | Real-time lyrical generation | Direct WebSocket + Stream audit |
| **ConsequenceStream** | Lamport-ordered event bus, replay | Publish/subscribe for coordination |
| **ConsequenceLedger** | AI usage metering | Studio displays cost from Ledger events |

```
                    ┌─────────────────────┐
                    │  ConsequenceStudio  │
                    │  (DAW + Doctor UI)  │
                    └─────────┬───────────┘
              WebSocket       │        Stream pub/sub
              (real-time)     │        (audit + coordination)
                    ┌─────────▼───────────┐
                    │  ConsequenceStream  │
                    └─────────┬───────────┘
              ┌───────────────┼───────────────┐
              ▼               ▼               ▼
      ConsequenceTheory  ConsequencePoet  ConsequenceLedger
```

## System boundaries (non-negotiable)

- **Studio** owns creator UX, supervision UI, content moderation at the UI layer, and session identity (`session_id`, `composition_id`, `user_id`).
- **Theory** owns musical analysis. Studio reads CMTE frames — never computes harmony/rhythm.
- **Poet** owns lyrical generation. Studio never calls LLM APIs for composition assistance.
- **Stream** is the system of record for cross-service audit and replay.
- **Poet WebSocket** is the low-latency path for `POET_TOKEN` streaming in the Doctor panel **Compose** mode.

## Dual integration paths

### Path 1: Direct WebSocket → ConsequencePoet (required)

- Endpoint: `{STUDIO_POET_WS_URL}/ws/{session_id}`
- Dev default: `ws://localhost:8000`
- Implementation: `packages/stream/src/poet-client.ts` (`PoetStreamClient`)
- UI: Doctor panel **Compose** mode + Poet right-panel tab (shared `poet-store`)

### Path 2: ConsequenceStream (production coordination)

- Endpoint: `STUDIO_STREAM_URL` (e.g. `ws://localhost:8001/stream`)
- Toggle: `STUDIO_ENABLE_STREAM=true`
- Studio publishes `LLMIntentSignal` and `SupervisionAction` for audit/replay
- Studio subscribes to `CMTEAnalysisFrame`, `PoetryGenerationEvent`, `AIUsageEvent`

## Musical context

`MusicalContextCache` (`packages/state/src/musical-context-cache.ts`) holds the latest Theory-derived snapshot. `getSnapshotForGeneration()` feeds `LLMIntentSignal.musical_context`. When Stream/Theory is unavailable, a transport-derived fallback is marked `is_stale: true`.

## Doctor panel — Compose mode

The Doctor panel has four modes: **Diagnose**, **Suggest**, **Execute** (harmonic Doctor), and **Compose** (Poet co-writer). Compose mode:

- No freeform chat — generation from musical context + constraint controls only
- Streams `POET_TOKEN` in real time
- Supervision controls (accept/reject/edit/branch/lock)
- Publishes audit events to Stream when enabled

## Session identity contract

| ID | Scope | Generated by |
|----|-------|--------------|
| `session_id` | Creator working session | Studio on session start |
| `composition_id` | Song/project | Studio on project open |
| `user_id` | Authenticated creator | Auth layer |
| `intent_id` | One generate click | Studio |
| `generation_id` | One Poet output | Poet |

## Dev workflow without Stream

1. Run Poet standalone: `docker compose up` in poet repo → `ws://localhost:8000`
2. Set `VITE_STUDIO_POET_WS_URL=ws://localhost:8000`
3. Leave `VITE_STUDIO_ENABLE_STREAM=false`
4. Open workspace → Doctor → **Compose** → Generate

## Strict prohibitions

- No imports from Poet or Theory Python packages
- No lyrical generation or direct LLM calls in Studio
- No musical analysis (chord detection, syllable counting) in Studio
- No bypassing Poet for AI lyric generation
- `schema_version: 1` unless coordinated across all repos
